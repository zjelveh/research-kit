# Rules (research-kit; apply in every session of this project)

- Fail hard: no fallbacks, approximations or workarounds without explicit approval; fix the root cause.
- Verify the premises before claiming a mechanism; check files, outputs and numbers rather than recalling them.
- Show every prose edit (paper, slides, notes, rules) as a full before/after; apply it only after approval.
- No citation from memory: every reference is checked against a retrieved source before it enters the .bib, notes, paper or slides.
- Report outcomes faithfully: say what failed, what was skipped and what is unverified.
- Say exactly what each quantity is and how it is computed ("the SD of the ATT across the 500 draws", not "spread"); never allude.
- Every result in the paper or slides, integers included, is a generated macro; never type a result by hand.
- Procedures live in /kit: skills; project rules in CLAUDE.md. Route every new lesson or preference through /kit:learn, never auto-memory.
- If the Codex CLI is installed, before reporting a change to 2+ code files, or a finished plan task, as done: run `/kit:review` and wait for it to finish. Its own fixes go into the next review, not a new one. Skip it only when the user waives it.
